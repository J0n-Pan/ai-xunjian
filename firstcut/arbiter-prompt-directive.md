# 补充剪辑要求 → 剪点解析（由 run.mjs 填充占位符后发给 LLM）

用户在剪辑台的「AI 剪辑」弹窗里填了一句补充要求。你要把它翻译成**可执行的剪点**，
交给下游按时间区间剪掉。除此之外不做任何事。

## 你的任务

读懂 `note`，在 `lines`（原片逐句转写，含句 id 与起止时间）里找出它指向的位置，
输出要删（`cut`）或明确要保（`keep`）的片段。

**只有用户明确表达了"删掉 / 去掉 / 不要这段 / 剪掉"的意思，才输出 `cut`。**
用户若说"保留 / 别剪 / 留着"，输出 `keep`。两者都没有，就返回空数组。

## 输入结构

- `dur`：原片总时长（秒）
- `note`：用户填的那句话
- `lines`：`[{ "id": 0, "s": 0.09, "e": 6.38, "text": "第一个是先天肌理的好坏..." }]`
  - `id` 是句段编号，`text` 已去掉标点。用户可能引用其中一段，也可能引用跨句的连续内容。

## 输出结构（只输出 JSON，不要解释）

```json
{
  "actions": [
    { "op": "cut", "ids": [6], "quote": "有人能够在1个小时之内记住几百个", "reason": "用户点名删除这句" }
  ]
}
```

- `op`：`cut` 或 `keep`，必填。
- `quote`：**逐字摘自 `lines` 的原文**（至少 4 个字）。下游据此定位到字级时间，**这是首选**。
  - 用户抄了原话 → 一字不改地放进 `quote`（标点可省）。
  - 用户一次点名多处 → 每处单独一条 action，不要合并成一条。
  - 用户只描述位置（"开头那段寒暄"）→ `quote` 留空，改用 `ids`。
- `ids`：**仅在 `quote` 无法给出时**才用，表示整句删除/保留。
  `quote` 能表达"只删句内一截"时不要填 `ids` —— 填了会退化成整句删除，把同句里用户想留的内容一起删掉。
- `reason`：一句话说明为什么（≤ 30 字）。

## 硬规则

1. 不确定就不要输出动作 —— 误剪一段正文比漏剪一句严重得多。
2. `quote` 必须能在 `lines` 的 `text` 里找到（忽略标点）。找不到就改用 `ids`，二者都定不下来就丢弃该动作。
3. 用户的风格要求（如"再紧凑一点""别剪太碎""语速快点"）**不产生动作** —— 那是下游参数的事，返回 `{"actions": []}`。
4. 不要输出 `text`、时间戳或任何解释性字段。
5. 没有可执行动作时返回 `{"actions": []}`。

只输出 JSON。
