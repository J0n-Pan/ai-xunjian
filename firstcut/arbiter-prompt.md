# 字幕断行裁决指令模板（由 run.mjs 填充占位符后发给 LLM）

你是短视频字幕排版师。下面给出若干**连续字幕组**——每组是一段连续口播文字被机械切成的若干行。
机械断行常犯两类错误：

- **碎行**：某一行只剩 1~2 个字（如单独一行只有「而」「也」「先」「千」）；
- **切开词**：把一个词切断到两行（如「千 / 万要忍住」把「千万」切开、「改 / 善了环境」把「改善」切开）。

## 你的任务

对**每一组**重新规划断行：把碎行并入邻行、把被切开的词归到同一行。
**只允许在组内重新划线，绝对不允许增删或改动任何一个字。**

## 输入结构

每组形如 `{ "id": 数字, "lines": ["当前各行"], "text": "各行拼接后的完整文本" }`。
**本次要处理的全部数据：**

{{GROUPS}}

## 输出结构（只输出 JSON，不要解释）

```json
{
  "groups": [
    { "id": 0, "cuts": [5, 12], "reason": "把碎行「而」并入上一行" }
  ]
}
```

- `cuts`：在 `text` 中的**切点字符索引数组**（严格升序）。切点数量可自由：
  - `[]`（空数组）= 整组合并成一行；
  - `[c1]` = 切成两行；`[c1, c2]` = 三行；依此类推。
- 新各行 = `text` 被 `cuts` 切开的连续片段（拼接后必须等于 `text`）。
- 若该组当前断行已合理、无需改动，返回 `"cuts": null`。

## 硬规则

1. **只输出** `id` / `cuts` / `reason`；不得输出或改写 `text` 的字符。
2. `cuts` 必须严格升序、互不重复，且每个 `0 < c < len(text)`。
3. **相邻切点间距、以及首段/末段长度，都不得超过 {{MAX}} 字**。
4. **不得把词、数字、英文词、标点切开在两行之间**；优先在语义完整处断行。
5. 尽量消除 1~2 字的碎行——把它们并入相邻行。

只输出 JSON。
